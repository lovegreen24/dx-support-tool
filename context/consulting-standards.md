## このドキュメントについて

このファイルは、中小企業DX伴走支援における「財務分析の切り口」「DX成熟度診断の評価軸」「提言書のトーン・構成」の**判断基準**を定義する共通コンテキストである。上記の依存エージェントは、作業開始時に必ずこのファイルを読み込み、ここに定義された切り口・評価軸・トーンに沿って自らの成果物（財務分析結果・DX成熟度スコア・補助金マッチング結果・提言書ドラフト）を生成する。

このファイルを変更した場合、依存エージェント5つすべてに矛盾が生じないか点検すること（単一性の原則）。

## 1. 財務分析の切り口

対象MCP: `analyze_working_capital`（運転資本分析）／`compare_cost_benchmark`（コストベンチマーク比較）

### 1-1 運転資本分析で何を重視するか

運転資本分析の目的は「黒字でも資金が回らなくなる」状態を事前に検知し、経営者が手を打てるタイミングで示すことである。以下の順で診断する。

1. **必要運転資金の算出**: 売上債権（売掛金・受取手形）＋棚卸資産 − 仕入債務（買掛金・支払手形）を基本式とし、回転期間（日数）ベースで水準を把握する。単月の残高だけでなく、直近数期の推移（増加傾向か・季節変動か）を必ず併記する。
2. **銀行残高リスクの診断**: 必要運転資金に対して手元資金・借入枠がどの程度カバーできているか（月商の何ヶ月分か）を算出し、資金ショートまでの猶予をイメージできる形で示す。
3. **増減要因の特定**: 回転期間が悪化している場合、その主因が「売上債権の滞留（回収条件・与信管理）」「棚卸資産の滞留（過剰在庫・不良在庫）」「仕入債務の圧縮（支払条件の厳格化）」のいずれかを切り分ける。原因を切り分けずに「運転資金が厳しい」とだけ述べない。
4. **打ち手への接続**: 診断結果は必ず「何を改善すれば運転資金負担が軽くなるか」という次の一手につながる形でまとめる（回収サイト短縮の交渉余地、在庫回転の改善余地、支払条件の見直し余地など）。数値の羅列で終わらせない。

### 1-2 コストベンチマーク比較で何を重視するか

固定費（人件費・地代家賃・水道光熱費・広告宣伝費等の主要費目）を業種別・売上規模別の目安値と比較し、削減余地を定量的に示す。

- **比較は費目単位で行う**: 「固定費全体が高い/低い」ではなく、費目ごとに「業種平均比でどの費目が突出しているか」を特定する。
- **削減の必然性と実行可能性を分けて評価する**: ベンチマークより高い費目でも、事業戦略上の投資（採用強化・出店戦略など）である場合は単純な「ムダ」として扱わない。数値の乖離だけでなく、乖離の背景（意図的投資か、放置による膨張か）をヒアリング結果と突き合わせて判断する。
- **削減見込み額は幅で示す**: 目安値との差分をそのまま「削減可能額」と断定せず、実行難易度（すぐ着手できる／交渉が必要／時間を要する）に応じて段階的な見込みとして提示する。

### 1-3 業種別目安値の考え方

業種別の目安値（回転期間・固定費比率等の水準）は、業種・規模・ビジネスモデルによって大きくばらつくため、以下の考え方で扱う。

- 目安値は**絶対基準ではなく相対比較の出発点**として使う。同業種内でもビジネスモデル（現金商売か掛け売り主体か、労働集約か設備集約か）によって適正水準は変わる。
- 目安値からの乖離を機械的に「問題」と判定しない。乖離の理由をヒアリング（登録済みの業種・従業員数・訪問メモ等）で裏取りしてから所見に反映する。
- 目安値データが薄い・古い業種については、その旨を所見に明記し、「参考値であり実態とは乖離する可能性がある」と留保をつける（潔癖性の原則：事実確認できていないことを断定しない）。
- 例（ある製造業クライアントの場合）: 原材料の仕入から製品販売までのリードタイムが長い業態では、棚卸資産の回転期間が一般的な小売業の目安値より長くなるのが通常であり、それ自体を問題視しない。

## 2. DX成熟度診断の評価軸

対象MCP: `assess_digital_maturity`

診断対象は以下の4領域とする（CLAUDE.mdのMCP構成・要件定義に準拠）。

| 領域 | 評価する主な観点 |
|---|---|
| 営業 | SFA/CRMの活用度、EC・オンライン販路の活用度、顧客情報の一元管理度 |
| 総務経理 | クラウド会計の導入度、電子帳簿保存法への対応度、経理業務の自動化度 |
| 労務 | 年末調整・社会保険手続きの電子化度、勤怠管理システムの活用度 |
| 社内基盤 | チャット・Web会議ツールの活用度、RPA導入度、電子契約の活用度 |

### 2-1 成熟度レベルの定義例

各領域は以下4段階（Lv0〜Lv3）で評価する。数値スコアだけでなく、必ずレベル名とその状態像をセットで示し、経営者が自社の立ち位置を直感的に理解できるようにする。

- **Lv0（未着手）**: 紙・手作業・電話/対面が中心。デジタルツールをほぼ使っていない、または個人のExcel管理に留まる。
- **Lv1（部分導入）**: 一部の業務・一部の担当者のみデジタルツールを使用。属人化しており、組織的な運用ルールがない。
- **Lv2（組織運用）**: 部署・業務全体でツールが定着し、運用ルール（誰が・いつ・何を入力するか）が明文化されている。ただし他領域・他システムとの連携は限定的。
- **Lv3（連携・活用）**: ツール間連携（データ二重入力の排除）が進み、蓄積データを意思決定（営業戦略・経理分析・労務計画等）に活用できている。

### 2-2 優先度付けの考え方

4領域すべてを同時に引き上げようとしない。以下の観点で改善優先度を判定する。

1. **リスクの高さ**: 法対応（電子帳簿保存法等）に関わる領域は、成熟度が低いほど優先度を上げる（コンプライアンスリスクは待ったなしのため）。
2. **投資対効果**: 成熟度を1段階上げるための労力・コストに対して、業務効率化・機会損失回避の効果が大きい領域を優先する。
3. **クライアントの実行余力**: どれだけ理にかなった改善でも、経営者・現場が同時に着手できる数には限りがある。ヒアリングで把握した経営資源（人手・予算・ITリテラシー）を踏まえ、着手可能な数（目安2〜3領域）に絞って提示する。
4. 例（あるサービス業クライアントの場合）: 労務がLv0で電子帳簿保存法対応も未着手という状況なら、社内基盤の高度化（RPA導入等）より先に、法対応に直結する総務経理・労務の底上げを優先提案する。

### 2-3 業種別ヒアリングの引き出し（改善提案アイデア）

ヒアリング・提言書作成の際、クライアントの業種に応じて「こういうAIエージェント活用が考えられる」という具体的な引き出しとして、以下の一覧を参考にする。これは改善提案の**出発点**であり、実際に提言書へ反映する際は、ヒアリング結果（経営課題・ITリテラシー・予算感）で裏取りしてから記載する。表の内容を機械的にそのまま提示しない（3-4の断定回避・潔癖性の原則と同様）。ここに挙げるのは代表例であり網羅ではない。他の改善余地がないかは都度ヒアリングで確認する。

| 業種 | 改善提案の方向性（ヒアリング時の引き出し） |
|---|---|
| 不動産 | 物件条件ヒアリング〜提案の自動化、入居者からの問い合わせへの一次対応自動化 |
| 飲食 | 多言語での予約受付、需要予測に基づく食材発注の最適化 |
| 士業（弁護士・税理士・社労士） | 相談内容の一次整理・論点抽出、申告書類ドラフトの自動生成 |
| EC・電子商取引 | 購買履歴に基づく商品レコメンド、問い合わせ対応の一次自動化 |
| 教育 | 生徒ごとの理解度に応じた教材提示、採点・成績集計等の事務作業自動化 |
| 医療・ヘルスケア | 来院前の症状ヒアリング、診療記録作成の音声入力支援 |
| 金融 | 残高照会・手続き案内の定型応答自動化、資産運用提案の個別最適化 |
| 製造業 | 設備の異常兆候の早期検知、マニュアル・手順書への自然言語での問い合わせ対応 |
| 小売業 | 需要予測に基づく自動発注、販促物（チラシ等）の作成支援 |
| 建設 | 工程表の自動作成・更新、現場映像解析による安全リスクの早期検知 |
| 物流・運送 | 配送ルートの最適化、配送状況問い合わせへの自動応答 |
| IT・テクノロジー | コードレビュー・不具合検出の自動化、社内ITヘルプデスクの自動応答 |
| 人材・HR | 応募書類の一次スクリーニング、面接日程調整の自動化 |
| マーケティング | コンテンツ・広告文の生成支援、競合・市場動向の定期レポート化 |
| 観光・旅行 | 多言語での観光案内、宿泊・交通を含む旅程提案の自動化 |
| 農業 | 生育状況モニタリングに基づく作業提案、病害虫の画像診断支援 |
| エンターテインメント | コンテンツ制作の素案生成、イベント集客施策の最適化 |
| 美容・サロン | 予約・カウンセリングの自動対応、来店履歴に基づくリピート促進施策 |
| 保険 | 事故受付・初動対応の自動化、契約更新時期の提案 |
| 介護 | 介護記録の音声入力・自動作成、見守り・異常検知 |

## 3. 提言書のトーン・構成

対象MCP: `generate_proposal_draft`

### 3-1 想定読者

提言書の一次読者は**中小企業の経営者本人**である。財務・IT の専門家ではない前提で書く。二次読者としてコンサルタント本人（提示前の最終レビュー・加筆修正者）がいることを常に意識する。

### 3-2 専門用語の使い方

- 専門用語（回転期間、DXレベル、運転資本、与信管理等）を使う場合は、初出箇所で一言だけ平易な言い換えを添える（例:「回転期間（お金が入ってくるまでの日数）」）。
- 数値は必ず「何と比べて・何を意味するか」をセットで書く。数値単体を並べない（例:「売掛金回転期間が45日→60日に悪化。回収が半月遅れている状態」）。
- 専門用語で権威づけしようとしない。平易さを優先し、正確性を損なわない範囲で言い換える。

### 3-3 優先順位の付け方

- 改善策は**着手の緊急度×効果の大きさ**で並べ替え、「まず何から着手すべきか」が一読でわかる順序にする（すべてを横並びで羅列しない）。
- 各改善策には概算コスト・実行の目安期間を併記し、経営者が着手可否を判断できる情報を揃える。
- 補助金情報（補助金マッチングの結果）は該当する改善策の直下に紐付けて示し、「この改善に使える補助金はこれ」という対応関係を明確にする。

### 3-4 断定を避ける書き方（コンサルタントの最終判断が前提）

提言書ドラフトは**そのまま経営者に提示される最終文書ではなく、コンサルタント本人が事実確認・加筆修正した上で提示する草案**である。この前提を踏まえ、以下を徹底する。

- 事実（決算書の数値・診断結果の数値）と、そこからの示唆・提案は明確に分けて書く。事実は断定形で書いてよいが、示唆・提案部分は「〜と考えられます」「〜をご検討いただくことをおすすめします」など、断定を避ける語尾を使う。
- クライアントの経営判断に関わる事項（人員配置、取引先変更、大型投資の可否等）について、AIが独断で「〜すべきです」と結論づけない。あくまで判断材料の提示に留め、最終判断はコンサルタントおよび経営者に委ねる文体にする。
- 不確実性がある推定（業種目安値との比較、補助金の採択可能性等）には、その旨を明記する（「目安値との比較であり実態と異なる場合があります」「採択を保証するものではありません」等）。フォールバックで問題を隠蔽しない。

### 3-5 構成テンプレ

提言書ドラフトは概ね以下の構成順とする。

1. **現状サマリー**（財務・DXの現在地を1〜2文で要約。経営者が最初に読む部分)
2. **財務分析結果**（運転資本・コストベンチマークの所見。1-1〜1-3の切り口に沿う）
3. **DX成熟度診断結果**（4領域のレベルと優先度。2-1〜2-2の切り口に沿う）
4. **改善提言（優先順位付き）**（3-3の優先順位に沿い、各施策に概算コスト・期間・該当補助金を併記）
5. **実行ロードマップ**（着手順序を時系列で示す）
6. **留保事項**（推定・目安値に基づく箇所、コンサルタントによる確認が必要な箇所の明記）

### 3-6 DX投資の必要性を裏付ける外部データの使い方

提言書で「なぜ今DXに取り組むべきか」を訴求する際、以下のような外部の公的機関調査データを参考情報として引用してよい。ただし数値は業界横断のマクロ統計であり、個別クライアントの状況を保証するものではないため、必ず出典を明記し、断定を避ける文体（3-4）で扱う。

- 現在の労働時間のうち、一定割合は技術的に自動化可能とされている（出典: McKinsey Global Institute, 2025）
- 定型的な事務・データ入力・問い合わせ対応など、ルールベース・反復型の業務ほど自動化の対象になりやすい傾向がある（出典: WEF Future of Jobs Report, 2025）
- 一方でAIを使いこなす人材・組織には新たな需要が生まれており、活用の有無による格差拡大が指摘されている（出典: PwC Global AI Jobs Barometer, 2025）

使い方の注意:

- 数値をそのままクライアントの業種・職種に当てはめて断定しない（「貴社の経理業務は近い将来なくなります」等の煽り文言は使わない）。「一般的にこの種の定型業務は自動化が進みやすい傾向にあります」という留保付きの書き方にする（3-4準拠）。
- 出典（機関名・年）を明記し、根拠不明の断定情報として扱わない（実証性の原則）。
- あくまで「DX成熟度診断の結果」「財務分析の結果」等、そのクライアント固有の事実に基づく提案を主とし、外部マクロデータは動機付けの補助情報として、現状サマリー冒頭または留保事項の近辺で軽く触れる程度に留める。

## 4. 固有名の扱い（汎用性維持）

このファイル、および本ファイルを参照する各エージェントの成果物は、特定のクライアント企業に固定化されない**汎用ロジック**として設計する。

- 本文（地の文）に実在・仮想を問わずクライアント固有の社名・個人名・具体的業種名を直接書き込まない。
- 業種や事例に触れる必要がある場合は、必ず「例（ある製造業クライアントの場合）」のように**ラベル内でのみ**用いる。ラベルの外（判断基準そのものを述べる文）には固有名を出さない。
- これにより、コンサルタントが担当するどのクライアントに対しても、同じ判断基準セットをそのまま適用できる状態を保つ。

## 5. 精度向上について（注記）

本ドキュメントは、CLAUDE.md記載のMCP構成（財務診断系8ツール・DX成熟度診断・補助金マッチング等）と、中小企業診断士・中小企業庁のDX推進ガイドライン等、一般的に確立された中小企業経営診断のベストプラクティスを土台に作成した。実際のクライアント案件データ（決算書解析結果・ヒアリングログ・提言書の採用実績等）はまだ蓄積されていない。

実データが揃い次第、@エージェント改善 で本ドキュメントおよび依存エージェントの精度を上げてください（特に1-3の業種別目安値、2-1の成熟度レベル判定基準、3-3の優先順位付けロジックは、実案件との diff を取って調整することを想定している）。

2-3（業種別ヒアリングの引き出し）は外部セミナー資料「業界別AIエージェント制作アイデア100選」を参考に、原資料の文言・具体的な企業事例には依らず汎用的な形へ独自に再構成した。3-6（DX投資の必要性を裏付ける外部データ）は同資料が引用していたMcKinsey Global Institute・WEF Future of Jobs Report・PwC Global AI Jobs Barometerの公開統計を出典として直接引用したものであり、資料自体の著作物（構成・具体的な企業事例の記述）は転記していない。
