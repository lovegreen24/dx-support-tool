## 1. 前提条件

### 1.1 認証方式

- 認証は単純な平文パスワード一致方式(`AuthContext.login`)。パスワードは環境変数 `VITE_DASHBOARD_PASSWORD`(`frontend/.env.local`)で管理する。
- ログイン成功時、`sessionStorage` のキー `dx-support-tool.authenticated` に `'true'` を保存する。ブラウザタブ/セッションを閉じると認証状態は失われる(`sessionStorage` のため)。
- ログアウト操作(または `sessionStorage` クリア)で認証状態は解除される。

### 1.2 未ログイン時のリダイレクト仕様

- `/` は `ProtectedRoute` でラップされている。`isAuthenticated === false` の場合、`<Navigate to="/login" replace />` により `/login` へ即時リダイレクトされる(ダッシュボードのDOMは描画されない)。
- `replace` 遷移のため、ブラウザの「戻る」で保護ページの表示前状態には戻らない。

### 1.3 ログイン手順(テスト前提操作)

1. `/login` にアクセスする。
2. パスワード入力欄に正しいパスワード(テスト環境の `VITE_DASHBOARD_PASSWORD` の値)を入力する。
3. 「ログイン」ボタンをクリックする(またはEnter送信)。
4. ログイン成功時は `/` へ遷移し、ダッシュボードが表示される。

### 1.4 テストスコープ外

- 本仕様書は進捗ダッシュボードページ単体の検証に限定する。他ページ(ログインページ単体の詳細仕様、ページ間導線・ナビゲーション遷移テストなど)は別ファイルで扱うため対象外とする。
- ログイン失敗時のエラーメッセージ表示など、ログインページ自体の詳細挙動は本仕様書では前提条件の確認に留め、詳細検証は含めない。

## 3. 補足

### 3.1 データソースについて

- クライアント一覧は`GET /api/clients`(自社DB/`ClientStore`集約)、案件進捗は`GET /api/case-progress`(案件管理MCP/M-010と同一のGoogleスプレッドシートを直接HTTPで読む`CaseProgressSheetClient`集約)から取得する実データである。件数・値に依存するテストケース(DASH-004〜007、DASH-014等)のアサーション値は、テスト実行時点の実データ(自社DB・Googleスプレッドシート「案件進捗」シートの内容)に合わせて設定すること。

### 3.2 選定要素について

- 本実装時点でテスト用の `data-testid` 属性は付与されていない。実装時はMUIコンポーネントが持つアクセシブルロール(`role="table"` / `role="row"` / `role="progressbar"` 等)や表示テキスト(見出し・ラベル文言)を基準にセレクタを設計すること。
- 提案書ステータスChipの色分け(DASH-015〜018)は視覚的な色検証が難しい場合、MUIの `color` prop に対応するクラス名(`MuiChip-colorDefault` / `MuiChip-colorWarning` / `MuiChip-colorSuccess`)の付与有無で代替検証してよい。
